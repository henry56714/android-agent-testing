# 06 开发计划、测试矩阵与验收

## 1. 先文档、后开发

本文是初始长期验收计划。0.1.0 已完成本地工具开发、公开样例及用户指定的本机模拟器验证；实际交付见 09–11。真机、Compose、最低 API 和远程 CI 保留为后续扩展矩阵，不能视为本次已经执行。

| 阶段 | 交付 | 退出条件 |
|---|---|---|
| D0 文档 | 范围、架构、配置、用例库、结果、测试与开源计划 | 文档之间无关键冲突，定义通用/项目边界 |
| D1 文件与核心 | 配置/catalog schema、只读检索、校验、doctor、计划冻结 | 无设备单元测试与异常路径通过 |
| D2 本地执行 | process runner、Gradle adapter、结果映射、报告 | 真实合成工程可运行；失败/超时/零测试不伪通过 |
| D3 UI 闭环 | ADB、Maestro adapter、设备租约、证据、持久化重放 | 模拟器与真机完成冒烟和失败验证 |
| D4 设备逻辑与通用性 | instrumentation、多模块与 SDK 宿主、APK-only | 两个不同源码工程及 APK-only 通过适配验收 |
| D5 发布候选 | 版本锁定、兼容矩阵、文档、许可证和发布检查 | 干净环境可复现，发布清单完成 |

D1 不做数据库、Web UI 或 MCP；先解决可验证的文件工作流。

## 2. 工具自身测试

| 对象 | 有意义的测试 |
|---|---|
| 配置 | 缺字段、未知 schema、DAG 环、多产物匹配、越界/symlink、缺环境引用 |
| 用例库 | 重复 ID、旧 revision 冲突、依赖变化、断裂引用、未完成写入恢复 |
| 选择与冻结 | 标签/路径组合、必需项排除、零用例、工作区变化、依赖闭包快照 |
| 进程管理 | 非零退出、超时、取消、子进程退出、日志截断与清理 |
| 报告解析 | JUnit 参数化命名、失败/error/skipped、截断 XML、缺报告、旧报告、数量不符 |
| 设备 | 无设备、多个设备、未授权/offline、断连、API/ABI 不符、签名冲突 |
| 门禁 | 部分通过、BLOCKED、隔离、重试变绿、cleanup 失败、取消与零测试 |
| 持久化 | 新进程重载、历史版本不变、快照损坏、证据过期与缺失 |

用替身进程和固定报告样本验证解析/失败分类，再用真实工具做集成。不能只用 mock 工具证明设备能力。

## 3. 公开合成工程

后续自行编写并授权公开的样例，不复制商业项目代码：

- **sample-todo**：Kotlin + Compose，基本 CRUD、权限拒绝、状态恢复、本地业务测试。
- **sample-worker-sdk**：Java + View 宿主、多模块 SDK、受控线程 gate、可配置超时、测试网络服务端；包含真实替换/取消和重复副作用验证。
- **APK-only**：使用同一个公开样例构建的 APK，在没有源码配置的独立测试目录运行黑盒测试，验证内部逻辑 case 正确标为不可用。

公开样例须包含一组可控缺陷：删除关键业务行为、破坏边界条件、让 worker 不恢复、制造 UI 断言失败。测试需要在缺陷版本失败、修复版本通过，以验证断言有效，而不是只展示绿色报告。

私有实际 App 可作为本地试点，但其代码、端点、测试数据、运行日志均不进入公共仓库；其结果也不能替代公开样例可复现性。

## 4. 设备与环境矩阵

首轮选择样例声明的最低 API、当前选定目标 API 和一个中间 API，至少一台 ARM64 真机及一台宿主支持 ABI 的模拟器。具体 API/系统镜像在 D3 doctor 实测后冻结，不以未准备的设备宣称支持。

核心静态/本地测试在 macOS/Linux CI 验证；设备测试区分环境是否实际可用。每个格子记录 tested/failed/not-run，不用一条“支持 Android”替代兼容矩阵。

首次记录 Gradle/JDK/AGP/Android SDK/Maestro/Python 版本组合；升级任一执行器后跑契约与设备冒烟。Windows 只有完成同等验证才列为支持。

## 5. 可靠性与耗时

固定回归在同一基线设备连续运行 10 次，保存每次结果和耗时。出现 flaky 先定位原因；零失败仅作为这个环境的验收证据，不作为全局可靠性保证。

本地阈值测试使用可控时钟/同步屏障，设备测试保留真实时钟。等待使用条件与硬超时，避免任意 sleep。记录冷/热构建耗时，不预先承诺执行时间。

fast/change/full 档位分别报告覆盖范围。设备运行资源清理、重放一致性和“故障不会伪 PASS”均为必需验收项。

## 6. 发布门槛

- 从干净 clone 按文档可以安装工具、运行公开样例。
- 两种源码工程及 APK-only 不修改通用核心即可接入。
- 保存的用例在新 Agent 会话及无 LLM CI 中重放。
- 必需断言失败、报告丢失、设备断连、测试未发现均不返回成功。
- 原生测试、元数据、源码/APK 与运行证据可追溯。
- release 测试不依赖意外打包的 debug 探针。
- 未测试平台与已知限制公开列明。
