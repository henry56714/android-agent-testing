# 07 GitHub 开源发布准备

## 1. 当前 Git 边界

工具位于独立目录，拥有独立 `.git` 和提交历史；不是某个 App 的子目录或嵌套仓库。当前只初始化本地仓库，GitHub remote 与公开发布在验证完成后配置。

仓库名暂定 `android-agent-testing`，命令名暂定 `aat`。首次发布前核验 GitHub/包仓库名称可用性和命名冲突；现阶段不声称占有这些名字。

## 2. 许可与依赖

自有通用代码采用 Apache-2.0；已加入完整 LICENSE、NOTICE、第三方依赖许可证副本和 THIRD_PARTY.md。贡献者仍需确保提交内容具备授权。

优先通过用户安装的 CLI 调用 Maestro、Gradle 和 Android SDK 工具；不默认重新分发其二进制。发布前按实际依赖清单检查 LICENSE/NOTICE 与分发要求，记录来源和锁定版本。上游版本/许可变化时更新清单。

公开合成样例使用自编代码和合成数据。引用第三方片段时保留原来源与适用声明。

## 3. 发布内容

可公开：通用源码、schema、模板、Agent 工作规范、工具测试、合成样例、兼容矩阵、技术文档。

不公开：接入 App 的私有源码、包名/内部端点清单、运行设备标识、账号/密钥、业务 fixture、截图日志、APK/AAR、源码快照。公共仓库的 Git 历史也必须遵守此边界，不能只在发布前删除工作区文件。

## 4. 发布顺序

1. 完成本地验收，写入实际测试版本、限制与已知问题（已完成，见 10；真机和扩展平台明确为未测）。
2. 完成 LICENSE、第三方声明、CONTRIBUTING、问题模板、SECURITY 联系方式和发布说明。
3. 检查待公开文件及完整 Git 历史是否含私有内容或凭证，确认构建产物排除。
4. 确定用户所属 GitHub 账号/组织与最终仓库名，创建公开仓库并推送。
5. 先发布 pre-1.0 版本，记录 schema/CLI 兼容策略；干净 clone 再验证安装与样例。

用户已提出最终开源目标，但当前未达到发布阶段。此阶段不创建远程仓库、不发布占位软件包，不把尚未执行的验证写成通过。

## 5. 版本策略

当前本地版本为 0.1.0；配置/result schema 单独版本化。兼容变更有迁移说明；旧运行记录只读保留，不通过迁移改写历史结果。发布后按验证范围递增版本。
